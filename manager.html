Supabase RLS Policy Fix

Why the sync failed & how to unlock it in 10 seconds

Why did this happen?
In PostgreSQL, Supabase tables have Row Level Security (RLS) enabled. When you click Sync to Supabase, an upsert (insert/update) query is sent. If the table doesn't have an RLS policy with WITH CHECK (true), PostgreSQL blocks the write for security.

Copy this SQL fix: 
-- 1. Grant table privileges to anon and authenticated roles
GRANT ALL ON TABLE public.staff TO anon, authenticated, service_role;

-- 2. Enable RLS and grant full read/write/upsert policy
ALTER TABLE public.staff ENABLE ROW LEVEL SECURITY;
DROP POLICY IF EXISTS "Allow read access to staff" ON public.staff;
DROP POLICY IF EXISTS "Allow manager write access to staff" ON public.staff;
DROP POLICY IF EXISTS "Allow all operations on staff" ON public.staff;
CREATE POLICY "Allow all operations on staff" ON public.staff
  FOR ALL USING (true) WITH CHECK (true);

Next Steps:

  1. Open your Supabase Dashboard.
  2. Go to SQL Editor on the left menu and click New Query.
  3. Paste the SQL above and click Run (or press Ctrl+Enter).
  4. Come back here and click Sync to Supabase again!
